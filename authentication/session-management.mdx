A session represents a single logged-in context for a user. Each login creates a new session backed by a refresh token. Users can have multiple active sessions (e.g. phone + laptop + browser).

## Listing active sessions

```bash
curl https://api.example.com/v1/sessions \
  -H "Authorization: Bearer <access_token>"
```

Response:

```json
{
  "sessions": [
    {
      "id": "sess_01HQ...",
      "device": "Chrome on macOS",
      "ip": "203.0.113.42",
      "location": "San Francisco, US",
      "created_at": "2025-06-01T10:00:00Z",
      "last_active": "2025-06-20T14:22:00Z",
      "current": true
    },
    {
      "id": "sess_02AB...",
      "device": "iPhone 15",
      "ip": "203.0.113.99",
      "location": "San Francisco, US",
      "created_at": "2025-05-15T08:00:00Z",
      "last_active": "2025-06-19T09:10:00Z",
      "current": false
    }
  ]
}
```

## Revoking a session

To log out from a specific device, revoke its session by ID:

```bash
curl -X DELETE https://api.example.com/v1/sessions/sess_02AB... \
  -H "Authorization: Bearer <access_token>"
```

## Logging out (current session)

Revokes the current session's refresh token:

```bash
curl -X POST https://api.example.com/auth/logout \
  -H "Authorization: Bearer <access_token>"
```

## Logging out everywhere

Revokes **all** sessions for the account:

```bash
curl -X POST https://api.example.com/auth/logout-all \
  -H "Authorization: Bearer <access_token>"
```

Use this after a suspected account compromise or a password change.

## Session lifecycle

```text
Login
  └── Session created (refresh token issued)
        ├── Token refreshed → session extended
        ├── User logs out → session revoked
        ├── Idle 30 days → session expires
        └── Security event (password change, suspicious replay)
              └── All sessions revoked
```

## Security recommendations

<AccordionGroup>
  <Accordion title="Rotate tokens on every refresh">
    Never reuse a refresh token. Issue a new one on every `/auth/refresh` call and invalidate the previous one.
  </Accordion>
  <Accordion title="Bind sessions to IP or device fingerprint">
    Optionally reject refresh requests from a significantly different IP or user-agent to detect token theft.
  </Accordion>
  <Accordion title="Show users their active sessions">
    Let users see and revoke sessions they don't recognise — this is a standard security feature in modern apps.
  </Accordion>
  <Accordion title="Revoke all tokens on password change">
    Always invalidate every session when a user resets or changes their password.
  </Accordion>
  <Accordion title="Set short access token lifetimes">
    Keep access tokens short-lived (10–15 min). This limits the damage window if a token is leaked.
  </Accordion>
</AccordionGroup>
