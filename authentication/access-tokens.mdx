An access token is a short-lived credential (default: **15 minutes**) that authorises a single API request. Include it on every request; never cache it to disk.

## Obtaining an access token

Call the login endpoint with valid credentials:

```bash
curl -X POST https://api.example.com/auth/login \
  -H "Content-Type: application/json" \
  -d '{ "email": "you@example.com", "password": "••••••••" }'
```

Successful response:

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "Bearer",
  "expires_in": 900,
  "refresh_token": "dGhpcyBpcyBhIHJlZnJlc2ggdG9rZW4..."
}
```

| Field | Description |
|-------|-------------|
| `access_token` | JWT to attach to API requests |
| `token_type` | Always `"Bearer"` |
| `expires_in` | Seconds until the access token expires (900 = 15 min) |
| `refresh_token` | Used to get a new access token — see [Refresh tokens](/authentication/refresh-tokens) |

## Sending the access token

Add the token to the `Authorization` header on every request:

```bash
curl https://api.example.com/v1/resource \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

<Warning>
  Never send tokens in URL query parameters — they appear in server logs and browser history.
</Warning>

## Handling expiry

When a token expires the API returns:

```json
{
  "error": "token_expired",
  "message": "Access token has expired. Please refresh."
}
```

**HTTP status:** `401 Unauthorized`

Your client should catch this response and [refresh the token](/authentication/refresh-tokens) automatically before retrying the request.

## Token anatomy

Access tokens are signed JWTs. You can decode the payload (do not trust it on the server — always verify the signature):

```json
{
  "sub": "user_01HQ...",
  "email": "you@example.com",
  "role": "member",
  "iat": 1718000000,
  "exp": 1718000900
}
```

<Note>
  Never store the access token in `localStorage`. Use an in-memory variable or a `Secure; HttpOnly` cookie managed by the server.
</Note>
