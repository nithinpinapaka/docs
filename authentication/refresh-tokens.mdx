A refresh token is a long-lived credential (default: **30 days**) that lets your app obtain a new access token when the current one expires — without asking the user to log in again.

## Refreshing an access token

When the access token expires, call the refresh endpoint:

```bash
curl -X POST https://api.example.com/auth/refresh \
  -H "Content-Type: application/json" \
  -d '{ "refresh_token": "dGhpcyBpcyBhIHJlZnJlc2ggdG9rZW4..." }'
```

Successful response:

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "Bearer",
  "expires_in": 900,
  "refresh_token": "bmV3UmVmcmVzaFRva2Vu..."
}
```

<Note>
  Each successful refresh issues a **new refresh token** and invalidates the previous one (token rotation). Store the new refresh token immediately.
</Note>

## Token rotation

The API uses **refresh token rotation** to limit exposure:

1. Client sends the current refresh token.
2. Server validates it, marks it as used.
3. Server returns a new access token **and** a new refresh token.
4. If the old refresh token is ever used again (potential replay attack), the server invalidates the entire token family and logs the user out.

## Recommended client flow

```text
Request to API
  ├── 200 OK → continue
  └── 401 token_expired
        ├── Call /auth/refresh with refresh token
        │     ├── 200 OK → store new tokens, retry original request
        │     └── 401 refresh_expired → redirect user to login
        └── done
```

In code (JavaScript example):

```js
async function apiRequest(url, options = {}) {
  let res = await fetch(url, withAuth(options));

  if (res.status === 401) {
    const refreshed = await refreshTokens();
    if (!refreshed) { redirectToLogin(); return; }
    res = await fetch(url, withAuth(options)); // retry once
  }

  return res;
}
```

## Refresh token expiry

| Scenario | Result |
|----------|--------|
| Not used for 30 days | Expired — user must log in again |
| User explicitly logs out | Immediately revoked |
| Potential replay detected | Entire token family revoked |
| Password changed | All refresh tokens for the account revoked |

## Storage

| Platform | Recommended storage |
|----------|---------------------|
| Web | `Secure; HttpOnly` cookie (server-managed) |
| Mobile (iOS/Android) | OS keychain / keystore |
| Desktop | OS credential store |

<Warning>
  Never store refresh tokens in `localStorage`, `sessionStorage`, or plain files — they can be stolen by XSS attacks or other processes.
</Warning>
