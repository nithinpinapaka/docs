Your server sends push notifications using the **Web Push Protocol** with VAPID authentication. The `web-push` npm package handles the encryption and HTTP request for you.

## Install the library

```bash
npm install web-push
```

## Configure VAPID keys

Set your keys once at startup (typically from environment variables):

```js
import webpush from 'web-push';

webpush.setVapidDetails(
  'mailto:support@example.com',    // contact email
  process.env.VAPID_PUBLIC_KEY,
  process.env.VAPID_PRIVATE_KEY,
);
```

## Send a push message

```js
async function sendPushNotification(subscription, payload) {
  try {
    await webpush.sendNotification(
      subscription,                         // stored PushSubscription object
      JSON.stringify(payload),
    );
  } catch (err) {
    if (err.statusCode === 410) {
      // Subscription has expired or was revoked — remove it from your DB
      await deleteSubscription(subscription.endpoint);
    } else {
      throw err;
    }
  }
}

// Example usage
await sendPushNotification(userSubscription, {
  title: 'New message from Alex',
  body: 'Hey, are you free today?',
  url: '/messages/123',
});
```

## API endpoint for triggering pushes

```js
// POST /api/push/send
app.post('/api/push/send', requireAuth, async (req, res) => {
  const { userId, title, body, url } = req.body;
  const subscriptions = await getSubscriptionsForUser(userId);

  await Promise.allSettled(
    subscriptions.map(sub =>
      sendPushNotification(sub, { title, body, url }),
    ),
  );

  res.json({ sent: subscriptions.length });
});
```

## Payload structure

There is no enforced schema — your service worker interprets whatever JSON you send. A recommended structure:

```json
{
  "title": "Notification title",
  "body": "Notification body text shown below the title",
  "url": "/path/to/open/on-click",
  "icon": "/images/icon-192.png"
}
```

## Error codes

| HTTP status | Meaning | Action |
|-------------|---------|--------|
| `201` | Delivered to push service | None |
| `400` | Invalid request or payload | Check payload and headers |
| `401` | VAPID authentication failed | Verify VAPID keys |
| `404` | Subscription not found | Remove subscription from DB |
| `410` | Subscription expired / revoked | Remove subscription from DB |
| `429` | Rate limited by push service | Retry with exponential back-off |

## Unsubscribing

Let users turn off notifications at any time:

```js
// Client-side
async function unsubscribe() {
  const reg = await navigator.serviceWorker.ready;
  const sub = await reg.pushManager.getSubscription();
  if (sub) {
    await sub.unsubscribe();
    await fetch('/api/push/unsubscribe', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', 'Authorization': `Bearer ${accessToken}` },
      body: JSON.stringify({ endpoint: sub.endpoint }),
    });
  }
}
```

Always remove the subscription from your database when the user unsubscribes — sending to a revoked endpoint wastes resources and may get your VAPID key flagged.
