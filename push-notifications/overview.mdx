Push notifications let you reach users on their devices through the browser or mobile OS — even when your site is not open. They are delivered via the **Web Push Protocol** and rely on a service worker running in the background.

## How it works

<Steps>
  <Step title="User grants permission">
    The browser prompts the user to allow notifications. This must be triggered by a user gesture (button click, etc.).
  </Step>
  <Step title="Browser creates a push subscription">
    After permission is granted, the browser generates a unique **push subscription** containing an endpoint URL and encryption keys.
  </Step>
  <Step title="Client saves the subscription">
    Your app sends the subscription object to your server so you know where to deliver notifications for that user.
  </Step>
  <Step title="Server sends a push message">
    When an event occurs (new message, alert, etc.), your server sends an encrypted payload to the push endpoint.
  </Step>
  <Step title="Service worker receives and shows it">
    The browser wakes the service worker, which calls `showNotification()` to display the alert — even if the tab is closed.
  </Step>
</Steps>

## Supported platforms

| Platform | Support |
|----------|---------|
| Chrome (desktop + Android) | Full support |
| Firefox (desktop + Android) | Full support |
| Safari (macOS 13+, iOS 16.4+) | Supported via Web Push |
| Samsung Internet | Full support |

<Note>
  iOS requires the site to be added to the Home Screen as a PWA before push notifications work on Safari/iOS 16.4+.
</Note>
